<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → POST /api/users | Untrusted role/username/password; privilege-escalation target |
| client → POST /profile | Untrusted password change input |
| concurrent workers → users.json | Multi-process write race |
| operator env → app secret | SECRET_KEY provenance |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-04-ESC | Elevation of Privilege | create_user / update_user | mitigate | ROLE_HIERARCHY index check: creator index must be strictly less than target; enforced server-side, never trust client role (test_privilege_hierarchy) |
| T-01-04-MASS | Tampering | create_user request body | mitigate | Whitelist username/password/role only; no `.update(request.json)`; grep gate asserts absence |
| T-01-04-LEAK | Information Disclosure | GET /api/users | mitigate | Strip password_hash from every user record returned to the client |
| T-01-04-RACE | Tampering | save_users concurrent write | mitigate | `fcntl.flock(LOCK_EX)` around the write; plus single-worker PM2 as defense-in-depth |
| T-01-04-PWLEN | Identification & Auth | weak password on create/change | mitigate | Enforce min length 8 on create_user and profile change |
</threat_model>
