<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| session cookie → require_role | Untrusted user_id must resolve to an active User row before any protected action |
| concurrent writes → SQLite | Multiple requests writing users/employees must not corrupt data once fcntl is removed |
| route input → ORM query | User-supplied ids flow into `.query.get()` / `.filter_by()` — must stay parameterized |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-07 | Elevation of Privilege | require_role ORM lookup | mitigate | `User.query.get` + `user.active`/`user.role` checks preserve the exact authorization logic; rbac tests assert privilege-escalation blocks still hold |
| T-06-08 | Tampering | concurrent writes after fcntl removal | mitigate | SQLAlchemy session transactions + SQLite serialization replace fcntl.flock (D-04/D-15); commit-once-per-operation prevents partial writes |
| T-06-09 | Injection | ORM .query.get/.filter_by | mitigate | SQLAlchemy parameterizes all query values; no `text()` with f-strings introduced (RESEARCH security domain) |
| T-06-10 | Denial of Service | LogEntry unbounded growth | mitigate | append_log enforces 10,000-row cap via ordered DELETE (D-03) |
</threat_model>
