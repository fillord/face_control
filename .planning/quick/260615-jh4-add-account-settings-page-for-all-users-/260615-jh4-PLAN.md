<objective>
Add a self-service account settings page available to ALL authenticated roles. A user can change their own password and their own display name. Implemented as a standalone `/account` page plus a `PATCH /api/me` endpoint that mutates only the current session user, with a nav link added to dept_admin, org_admin, and superadmin pages.

Purpose: Every user — not just admins managing others — needs a way to update their own credentials and the name shown in the UI.
Output: `display_name` column on User, `/account` route, `PATCH /api/me` endpoint, `account.html` template, three nav links.
</objective>

<decisions>
- D-01: "Display name" is implemented as a NEW `User.display_name` column (nullable String), NOT a username change. Username is the login identity and stays immutable here. This is the full feature, not a v1 reduction — username editing is out of scope by design, display_name is the user-facing label.
- D-02: Build a NEW standalone `/account` page rather than reusing `/profile`. `/profile` (password-only) is left untouched to avoid regressions; `/account` is the superset (password + display name) the task requests. Nav links point to `/account`.
- D-03: `PATCH /api/me` derives the target user exclusively from `session["user_id"]` — it never accepts a user id from the client body. This is the security boundary that makes "current user only" enforceable server-side.
- D-04: Where `display_name` is shown: the header `user-badge` continues to show `username` (session value) to avoid touching every page's session plumbing; `account.html` displays/edits `display_name`. Updating the badge everywhere is out of scope for this quick task.
- D-05: All UI text in Russian per project conventions.
</decisions>

  <name>Task 2: Add GET /account route and PATCH /api/me endpoint</name>
  <files>app.py</files>
  <action>
Add two routes near the existing /profile route (after line 1059).

(1) `@app.route("/account")` + `@require_role()` (bare = any authenticated role per app.py:96-111). Handler loads `user = User.query.get(session.get("user_id"))`, then `return render_template("account.html", username=user.username if user else "", display_name=(user.display_name or "") if user else "")`.

(2) `@app.route("/api/me", methods=["PATCH"])` + `@require_role()`. Per D-03, resolve target via `user = User.query.get(session.get("user_id"))` ONLY — never read an id from the request body. If no user, return `jsonify({"error": "Не авторизовано"}), 401`. Parse `data = request.get_json(silent=True) or {}`.
  - If `"display_name"` in data: set `name = data["display_name"].strip()`; if longer than 128 chars return `jsonify({"error": "Имя слишком длинное"}), 400`; assign `user.display_name = name or None`.
  - If `"new_password"` in data: require `current_password` to match via `bcrypt.checkpw(data.get("current_password","").encode(), user.password_hash.encode())` — on mismatch return `jsonify({"error": "Текущий пароль введён неверно"}), 400`; enforce `len(new) >= 8` else `jsonify({"error": "Пароль должен содержать не менее 8 символов"}), 400`; then `user.password_hash = bcrypt.hashpw(new.encode(), bcrypt.gensalt()).decode()`. Mirror the bcrypt usage from app.py:1045-1053 and validation from app.py:1564-1566.
  - Wrap `db.session.commit()` in try/except: on exception `db.session.rollback()` and return `jsonify({"error": "Internal server error"}), 500`.
  - On success return `jsonify({"status": "updated", "display_name": user.display_name or ""})`.
Do not inline any other user's id; do not add username editing.
