## Spacing Scale

Declared values (multiples of 4 only):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge padding, inline element separation |
| sm | 8px | Compact element spacing, button margin-top, gap between nav items |
| md | 16px | Default form group margin, standard element spacing |
| lg | 24px | Section padding (`.page` padding-top), card padding |
| xl | 32px | Card padding (`.card` in login), logo margin-bottom |
| 2xl | 48px | Logo icon size (48x48), page-level vertical rhythm |
| 3xl | 64px | Not currently used; reserved for major section breaks if needed |

**Exceptions:** Input padding uses 11px vertical (non-standard) — this is the existing pattern in login.html and must be preserved to avoid visual regression. Do not normalize to 12px.

## Typography

| Role | Size | Weight | Line Height | Source |
|------|------|--------|-------------|--------|
| Body / table cell | 13px | 400 | 1.5 | Extracted from admin.html `td`, `.stat-label`, `.sub`, `label` |
| Input / body prominent | 14px | 400 | 1.5 | Extracted from login.html `input`, admin.html `select` |
| Label / tab / button | 14px | 600 | 1.4 | Extracted from `.tab`, `.btn`, `button` elements |
| Heading / card title | 18px | 600 | 1.2 | Extracted from `h2` (18px, weight 600) |

**Weights in use:** 400 (regular) and 600 (semibold) — exactly 2 weights. Weight 700 is a brand exception used only for the logo wordmark (`.logo-text`) and must not be used elsewhere; it is not a typography scale entry.

**New templates must follow these sizes exactly.** Specifically:
- `dashboard.html` body text: 13px weight 400 line-height 1.5
- `dashboard.html` heading: 18px weight 600 line-height 1.2
- `profile.html` form labels: 13px weight 400 (body weight — 500 eliminated)
- `403.html` heading: 18px weight 600; body copy: 13px weight 400
- User management tab in admin.html: follow existing `td`/`th` sizes (13px body, 11px uppercase headers)

## Interaction Contracts

### Login form (`/login`)

- No visual changes to the form
- Error message uses existing `.error` class: background #FFEBEE, text #B71C1C, border #EF9A9A
- On submit: standard HTML form POST — no JavaScript submission
- Autofocus: username field (already present)
- Redirect on success: server-side redirect (no JS redirect)

### 403 Forbidden page

- No interactive elements except one link: "← Вернуться к панели"
- Link renders as `.btn` (full-width accent button, same as login submit button)
- No animation, no retry mechanism
- HTTP 403 set on response

### Dashboard page (`/dashboard`)

- Static informational page — no interactive elements in Phase 1
- Shows: user's name (prominent, 18px weight 600), role label (13px weight 400 in #78909c), and placeholder message
- No navigation tabs — single content area
- Header identical to admin.html header (logo + user badge + logout button)

### Profile page (`/profile`)

- Form with three fields: Текущий пароль, Новый пароль, Повторите новый пароль
- Uses identical `.form-group` / `label` / `input` / `.btn` pattern from login.html
- Success state: green inline message (background #E8F5E9, text #1B5E20, border 1px solid #A5D6A7)
- Error state: `.error` class (existing pattern)
- Submit button label: "Сменить пароль"

### User management tab (in admin.html)

- Role filter select: only roles the current user can manage appear as options (enforced server-side; Jinja2 renders only valid options)
- Create form: same `.card` visual style as login, rendered inline below toolbar, hidden by default, toggled by "Создать пользователя" button
- Deactivate confirmation: `window.confirm()` dialog — "Деактивировать пользователя {username}? Они не смогут войти до повторной активации." Standard browser confirm, no custom modal.
- Reactivate button (for deactivated users): "Активировать" in accent color

### Role-scoped navigation (admin.html)

Navigation tab visibility rules (Jinja2 `{% if %}`):

| Tab / Link | Visible to |
|-----------|------------|
| Журнал посещаемости | superadmin, org_admin, dept_admin |
| Статистика за месяц | superadmin, org_admin, dept_admin |
| Пользователи (new tab) | superadmin, org_admin, dept_admin |
| ← Киоск link | all authenticated roles |
| Выйти | all authenticated roles |

Viewer and employee roles are redirected to `/dashboard` — they never reach `/admin`, so nav gating there is defense-in-depth only.
