<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /login | Untrusted username/password crosses into auth logic |
| browser session cookie → @require_role | Signed cookie carries identity; tampering must be detected |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-02-SF | Spoofing | login_page session set | mitigate | `session.clear()` before writing new session keys (session-fixation defense, ASVS V3) |
| T-01-02-PW | Spoofing | bcrypt.checkpw | mitigate | Verify against stored bcrypt hash with `.encode()` on both args; never compare plaintext (ASVS V2) |
| T-01-02-RH | Tampering | init_users MIG-03 | mitigate | Copy config.json hash verbatim; re-hashing breaks login and is asserted against in test_init_users_migrates_hash |
| T-01-02-AC | Elevation of Privilege | require_role active check | mitigate | Inactive user is redirected to /login, not granted access; check runs before role check (D-05 order) |
| T-01-02-SK | Information Disclosure | SECRET_KEY hardcoded fallback | accept (this plan) | Session signing key hardening is handled in plan 01-04 (ecosystem.config.js env injection); accepted here to keep the skeleton thin |
</threat_model>
