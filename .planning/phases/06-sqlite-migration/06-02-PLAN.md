<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → /login (require_role) | Untrusted session cookie; user lookup must resolve against the DB, not stale file state |
| test process → DB | In-memory DB must be isolated per test so one test's rows never leak into another |
| startup → data/app.db | First run must create the file at the intended absolute path, not the Flask instance path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-03 | Spoofing | init_users MIG-03 hash copy | mitigate | init_users reads the legacy bcrypt hash from AppSetting and stores it verbatim; test_auth login test asserts superadmin login still works |
| T-06-04 | Information Disclosure | test DB isolation | mitigate | client fixture calls db.drop_all() in teardown; in-memory `:memory:` DB is per-connection, preventing cross-test data leakage |
| T-06-05 | Tampering | app.db path resolution | mitigate | default URI uses os.path.abspath(__file__) join (Pitfall 8) so the DB lands in data/, not the instance path |
| T-06-06 | Denial of Service | db.create_all order | mitigate | startup calls db.create_all() before init_users() (Pitfall 2), preventing "no such table: user" crash on first run |
</threat_model>
