<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /api/orgs, /api/depts, /api/employees | untrusted JSON crosses; client may forge org_id/dept_id to escalate |
| session → write authorization | session org_id/dept_id set at login; relied on for scope decisions |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-E1 | Elevation | dept_admin calling /api/orgs DELETE or other-dept writes | mitigate | @require_role("superadmin") on all org write routes; dept_admin scope gate to session dept_id on employee create |
| T-02-T4 | Tampering | org_admin POSTs dept with another org's org_id | mitigate | create_dept/update_dept/delete_dept check target org_id == session org_id, else 403 (Security Domain table) |
| T-02-T5 | Tampering | mass-assignment: PATCH employee with attacker-supplied label/name | mitigate | update_employee_assignment + add_employee whitelist fields; never copy request.json into record |
| T-02-T6 | Tampering | stale session org_id after that org deleted | mitigate | write routes verify referenced org/dept still exists in store before acting (Anti-pattern: trusting session) |
| T-02-D2 | Denial of Service | deleting org/dept orphans employees | mitigate | delete_org/delete_dept return 409 if employees reference the entity (Open Question 1) |
| T-02-SC | Tampering | npm/pip installs | accept | No new packages this phase; legitimacy gate N/A |
</threat_model>
