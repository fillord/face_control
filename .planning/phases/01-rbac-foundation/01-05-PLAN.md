<objective>
Runtime hardening slice: replace the hardcoded session-signing key with a strong SECRET_KEY injected via PM2, and pin the process to a single gunicorn worker so the JSON store is never written by two workers concurrently. This finalizes the secure deployment posture for Phase 1.

Purpose: `app.py` line 10 already reads `os.environ.get("SECRET_KEY", "<hardcoded fallback>")`. RESEARCH Open Question 2 / Security Domain flagged the hardcoded fallback as an Information Disclosure risk (any code reader can forge sessions). Open Question 1 + STATE.md require a single Flask worker. This plan creates `ecosystem.config.js` (the only autonomous artifact) and a blocking human-action checkpoint where the operator generates a secret, applies the PM2 config, and confirms login still works. Isolated in its own plan because it pairs an unavoidable operator action with a process restart (no implementation tasks share this plan).
Output: `ecosystem.config.js`; live PM2 process running with injected SECRET_KEY and a single worker.
</objective>
