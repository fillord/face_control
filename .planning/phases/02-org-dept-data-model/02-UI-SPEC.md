# Phase 2 — UI Design Contract: Org/Dept Data Model

> All values sourced from existing codebase (admin.html, dashboard.html, kiosk.html) and CONTEXT.md decisions.

## Spacing Scale

Declared values (multiples of 4 only). Extracted from existing templates:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps within badges, inline margins |
| sm | 8px | Gap between header controls, badge internal padding |
| md | 16px | Card internal padding top/bottom, form group spacing |
| lg | 24px | Page horizontal padding, header padding, section top margin |
| xl | 32px | Card padding (full-bleed cards), major layout gaps |
| 2xl | 48px | Not declared explicitly — avoid; use xl + lg combination |
| 3xl | 64px | Not used in admin pages — avoid |

**Exceptions (inherited from admin.html — matched verbatim for visual consistency):**

| Token | Value | Usage |
|-------|-------|-------|
| xs-alt | 6px | Destructive/edit button vertical padding (`padding: 6px 12px`) |
| sm-alt | 12px | Table cell padding, destructive button horizontal padding, input vertical padding (`padding: 8px 12px`) |
| md-alt | 20px | Nav tab horizontal padding (`padding: 12px 20px`) |

These three values appear in the existing admin.html and are carried forward verbatim. Do not introduce additional off-scale values.

Derived values in active use:
- Stat cards: `padding: 16px` (square padding)
- Table cells: `padding: 12px 12px` (th), `padding: 12px 12px` (td)
- Header: `padding: 16px 24px`
- Nav tabs: `padding: 12px 20px` per tab item
- Button padding: `8px 16px` for primary and secondary action buttons; `6px 12px` for destructive/inline edit buttons

## Typography

| Role | Size | Weight | Line Height | Notes |
|------|------|--------|-------------|-------|
| Body | 13px | 400 | 1.5 | Table cells, form labels, badges, user-badge, general copy |
| Label | 11px | 600 | 1.2 | Table headers (th), stat-label, uppercase with letter-spacing 0.05em |
| Heading | 16px | 600 | 1.2 | Logo text, card titles, section headings (h3 in forms) |
| Display | 26px | 600 | 1.0 | Stat values (.stat-val) — numeric figures only |

**Rule:** Exactly 2 font weights are used: 400 (body/regular) and 600 (emphasis — labels, headings, display, nav tab active text, buttons). Do not introduce weight 500 or any other weight. Do not introduce any new font sizes beyond these four. All text is `color: #1a2340` (body) or `color: #546e7a` (muted/secondary).

## Interaction Contracts

### Inline Form Toggle

Pattern: button click shows/hides a form panel directly above or below the table. Used for "Add org", "Add dept", "Edit schedule". No page navigation. On submit success: hide form, reload table data via fetch, show brief success toast (if toast pattern exists) or refresh table HTML in place.

### Inline Edit Actions

"Edit" and "Delete" action buttons appear in a `.actions` column in each table row. Edit opens an inline form pre-populated with the record's current values. Delete triggers `window.confirm()` with the destructive confirmation copy above.

### Schedule Edit Form Fields

```
Начало рабочего дня: <input type="time" value="09:00">
Конец рабочего дня:  <input type="time" value="18:00">
Рабочие дни: checkboxes [Пн] [Вт] [Ср] [Чт] [Пт] [Сб] [Вс] (pre-check Mon–Fri)
```
Checkbox labels use Cyrillic abbreviations matching ISO weekday order.

### Department Dashboard Live Data (DASH-02)

Present/absent/late counts update on page load via a single `fetch('/api/dept_attendance_today')` call. No polling. Table rows for absent employees show a grey `.badge-absent` badge. Table cells for check-in times show `—` when absent.

### Kiosk Dept Name (KIOSK-01)

The `dept_name` field is returned in the `/api/recognize` JSON response. `kiosk.html` JavaScript reads `data.dept_name` and sets `innerText` on a `<div class="emp-dept">` element. If `dept_name` is falsy, the element remains hidden via `display:none`.
